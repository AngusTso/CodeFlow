Agents
Goal: Design a responsive web-based frontend prototype for an AI-powered short video creation platform. The goal is to showcase your ability to design intuitive, visually appealing, and functionally coherent interfaces for AI-driven creative workflows

Platform introduction: It enables users to create short videos (15–60 seconds) by leveraging AI generation tools for storyboard creation, scene generation, character design, and automated video composition.
Core features (4 modules):

1. Storyboard Generator Interface
   ◦ Input field for video concept/prompt (e.g., "A cyberpunk city at night with neon lights").
   ◦ AI-generated storyboard display: sequence of keyframes or scene thumbnails with descriptions.
   ◦ Interactive timeline showing scene order, duration, and transitions.
   ◦ Ability to reorder, delete, or regenerate individual scenes.

2. Scene Generation Module
   ◦ Visual selection of scene types (e.g., urban, nature, sci-fi, fantasy, abstract).
   ◦ Parameter controls: lighting, color palette, mood, camera angle, and style (realistic, cartoon, 3D render, etc.).
   ◦ Preview area showing AI-generated scene drafts with regeneration options.

3. Character Generator Module
   ◦ Character customization interface: appearance, clothing, expressions, and poses.
   ◦ AI-suggested character templates (e.g., "Futuristic Detective," "Fantasy Warrior," "Casual Vlogger").
   ◦ Integration with scenes: show how characters fit into generated environments.

4. Video Composition Preview
   ◦ Basic timeline editor showing combined scenes, characters, and audio tracks.
   ◦ Playback simulation: auto-play generated video preview with transitions.
   ◦ Export/share options (simulated): resolution selection, format, and platform optimization (TikTok, Instagram Reels, YouTube Shorts).

Design requirements

1. Responsive Design
   • Mobile-first approach: ensure usability on screens as small as 320px.
   • Tablet and desktop layouts with adaptive navigation and controls.
   • Touch-friendly interactions for mobile users.

2. Each prototype must be a standalone HTML5 file (with embedded CSS and JavaScript) that can be opened directly in a browser.

- Use modern frameworks/libraries via CDN if needed (e.g., Tailwind CSS, Bootstrap, Vue.js, React via CDN, or vanilla HTML/CSS/JS).

All prototypes must be fully responsive and include:

1. Unique Visual Theme: Each prototype should have a distinct aesthetic (e.g., minimalist, cyberpunk, retro, corporate, playful, dark mode, glassmorphism, etc.)

2. Different Interaction Patterns: Vary how users navigate and interact (e.g., drag-and-drop, wizard-style steps, card-based layout, voice input, gesture controls).

3. Varied Layout Structures: Experiment with grid, sidebar, fullscreen, split-screen, and modal-based designs.
4. Diverse Color Schemes & Typography: Show range in visual design while maintaining accessibility (WCAG 2.1 AA contrast ratios).

Suggested Differentiation Axes (Apply to Each Prototype)

1. Target user persona (e.g., professional marketer, casual creator, filmmaker, educator)
2. Device priority (mobile-first vs. desktop-first).
3. AI interaction style (text prompts, voice commands, preset templates, drawing input).
4. Visual complexity (minimalist vs. feature-rich dashboard).
5. Animation/transition effects (subtle vs. dynamic).
6. Navigation style (top nav, side nav, bottom tab bar, hamburger menu).

Technical Requirements

1. HTML5 Standards: Use semantic HTML5 elements (<header>, <nav>, <main>, <section>, <article>, <footer>).
2. CSS3: Use Flexbox/Grid for layouts, media queries for responsiveness, and CSS variables for theming.
3. JavaScript: Implement interactive elements (e.g., dynamic storyboard updates, simulated AI generation with mock data, timeline editing).
4. No Backend Required: Simulate AI generation with pre-defined mock data or random generators. Do not implement actual AI models.
5. Performance: Each prototype should load quickly (optimize images, minify code where possible).
6. Accessibility: Include ARIA labels, keyboard navigation support, and alt text for images.

Deliverables

1. 3 Separate HTML5 Prototype Files
   ◦ Name them descriptively (e.g., prototype-01-minimalist-mobile.html, prototype-02-cyberpunk-desktop.html, prototype-03-professional-creator.html).
   ◦ Each file must be self-contained and runnable in a modern browser (Chrome, Firefox, Safari).
2. Design Rationale Document (1–2 pages)
   • Explain the design decisions for each prototype.
   • Highlight how each prototype addresses different user needs or scenarios.
   • Discuss trade-offs (e.g., simplicity vs. functionality, mobile vs. desktop focus).
3. Responsive Design Testing Report
   • Screenshots or descriptions of how each prototype adapts to at least 3 screen sizes (mobile: 375px, tablet: 768px, desktop: 1440px).
   • Note any breakpoints used and how layouts change.
4. 2-Minute Screen Recording
   ◦ Demonstrate the key interactions of all 3 prototypes (e.g., navigating the storyboard generator, adjusting scene parameters, previewing the final video).
5. Live 10-Minute Demo + Q&A
   ◦ Present your design approach, walk through the 3 prototypes, and discuss your design philosophy.

Evaluation Criteria
• Creativity & Variety: How distinct and innovative are the 3 prototypes?
• Usability: Are the interfaces intuitive and easy to navigate?
• Responsiveness: Do prototypes adapt seamlessly across devices?
• Technical Execution: Is the code clean, efficient, and standards-compliant?
• AI Workflow Integration: How well does the design support the AI generation process (storyboard → scene → character → video)?
• Accessibility & Inclusivity: Are designs usable by people with disabilities?
• Documentation: Is the design rationale clear and well-articulated?

A Few Tips
• Focus on Frontend Design: This is a design task, not a backend or ML task. Do not implement actual AI models or video processing.
• Mock Data is Fine: Use placeholder images (e.g., via Lorem Picsum or Unsplash) and simulated AI responses.
• Prioritize User Experience: Think about how real users would interact with AI tools. Avoid cluttered interfaces.
• Test on Real Devices: If possible, test prototypes on actual phones/tablets to ensure touch interactions work well.
• Be Honest About Limitations: If a design choice has drawbacks (e.g., "This layout works best on desktop"), note it in your rationale.
